# Per-stage design choices (A2 deliverable)

This document covers the A2 knowledge-base build: framing plus Stages 1–4.
It deliberately excludes retrieval, agent, RL, and serving decisions, which
belong to later milestones.

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| **0. Frame** | Build a searchable, auditable evidence base from a scanned Bengali crop-disease textbook. A2 produces retrieval-ready evidence, not generated answers. | 403 source scans and about 116,539 words. The KB scope is 378 chapter pages; 25 auxiliary scans are excluded. Chapter-grouped splits are 264 train, 57 validation, and 57 test pages. | Configuration is the source of truth for all selected A2 models and parameters. | Chapter ranges and split lists prevent chapters appearing in more than one split. Held-out test labels are excluded from indexing and tuning. | `Page` identifies a source scan, `Region` holds layout metadata, and `Chunk` is the retrieval unit. Page IDs are retained through all stages. | EDA inspected dimensions, gutters, columns, skew, and scan-quality variation before the settings were chosen. | Batch build, with a CPU-safe committed configuration. The standalone Kaggle OCR runner can explicitly use a supported GPU. | `snapshot()` deterministically hashes a corpus; `validate()` checks pages and chapter splits. Both utilities exist but are not yet called inside `build_knowledge_base()`. |
| **1. Ingest + preprocess** | Reduce adjacent-page leakage and mild skew without damaging Bengali diacritics, conjuncts, or faint strokes. | Raw images under `data/raw/krishipath` are immutable inputs. Derived images are written under `data/interim/preprocessed`. | Pillow handles image/EXIF orientation; OpenCV provides Hough-line skew estimation. No learned enhancement model is selected. | EXIF transpose; 80 px left trim; 0 px uniform border trim; rotate only for a consensus skew between 0.15° and 2.0°. Denoising, whitening, sharpening, and binarization are disabled. | The processed file replaces only `Page.image_path` in the in-memory record; raw IDs and raw images remain unchanged. | Stronger crops, adaptive binarization, background normalization, and denoising were tried and made some pages look worse or increased OCR error. | Pillow/OpenCV run on CPU. This is the committed reproducible baseline. | Parameters are recorded in `config.yaml`; raw images and their derived counterparts remain separately identifiable. |
| **2. Layout** | Capture headings, paragraphs, lists, tables, figures, and approximate reading order as structural evidence without treating imperfect boxes as OCR boundaries. | Each processed page yields labelled coordinates and a page ID. Layout does not alter OCR text or the source image. | **Selected:** `juliozhao/DocLayout-YOLO-DocStructBench` through DocLayout-YOLO / YOLOv10. **Compared:** Docling, Qwen3-VL, Surya Layout, and DocLayout-YOLO. | Use `imgsz=1024`, `score_thr=0.20`, and top-to-bottom sorting. Labels map to `heading`, `table`, `figure`, or `text`. Public weights are cached after first download. | Boxes become `Region` metadata and a page metadata map. OCR reads the full processed page once because region-cropped OCR omitted boundary characters and content. | Representative Bengali-page overlays were compared for coverage, grouping, and reading-order usefulness. DocLayout-YOLO produced the most coherent practical output. | The committed baseline uses CPU because the teammate's detected `sm_120` GPU is not supported reliably by its installed Torch build. A compatible Kaggle GPU can be selected explicitly for experiments. | Region kind, box coordinates, model identifier, and threshold can be retained with run outputs; overlays provide inspectable evidence. |
| **3. OCR** | Transcribe printed Bangla conjuncts, vowel marks, numerals, punctuation, and embedded English/Latin crop-pathology terms. | OCR uses only the 378 chapter pages. The 57 held-out labelled pages are evaluation-only and are not used for training, preprocessing selection, or index input. | **Selected:** pretrained EasyOCR with `languages: [bn, en]`. **Compared:** Tesseract, Surya OCR, and EasyOCR. | Full-page recognition at `min_confidence=0.0`; sort lines by top/left coordinates; normalize Unicode to NFC and collapse whitespace; emit one source OCR chunk per page before tokenizer splitting. | Layout remains provenance metadata, not a hard OCR crop. Each source chunk retains document and page identity. | Surya OCR worked well locally on a teammate's RTX 4060 Ti. EasyOCR was selected because it handles the Bengali/English mix and can run directly on CPU, unlike the less reproducible Surya deployment path. Exploratory full-page EasyOCR results over 57 held-out pages were CER 0.3210, WER 0.4529, and character F1 0.7794; box-cropped OCR was worse (0.4411, 0.5957, 0.7237). These require rerunning after manual label review before final reporting. | Committed configuration uses CPU for a reliable autograder baseline. A compatible GPU may be specified in a Kaggle-only run; `auto` is not used because CUDA availability alone does not prove runtime compatibility. | Persist OCR text with page/document metadata, model/language settings, and normalized held-out CER/WER/F1 measurements. |
| **4. Index** | Retrieve Bengali crop-disease evidence efficiently while preserving a trace from a result to its OCR text and source page. | Index OCR output from the 378 in-scope pages only. Held-out reference labels are excluded. | `BAAI/bge-m3` at 1024 dimensions, with FAISS `IndexHNSWFlat`. | NFC-clean text is paragraph-grouped and BGE-tokenized into 256-token chunks with 32-token overlap. Vectors are L2-normalized; HNSW uses inner-product similarity with `M=32`, `efConstruction=40`, and `efSearch=64`. | Persist `index.faiss`, `chunks.jsonl`, and `metadata.json`. Chunk records include IDs, document IDs, page IDs, and text. | A teammate-provided 384-dimensional prototype index could self-retrieve but is not accepted as final evidence: it does not match BGE-M3's configured dimension, model provenance, or chapter-only scope. | BGE-M3 can run on CPU for correctness but is slower; a compatible Kaggle GPU is recommended for the one-off full-corpus build. | Index metadata records vector count, dimension, metric, and HNSW settings. The final build should additionally record the corpus hash and effective configuration. |
| **5. Retrieval** | Return the most relevant OCR passages for a Bengali question and expose how strong the evidence is, so the agent can tell good from weak evidence. | 378 in-scope pages indexed as 256-token chunks; 57 held-out pages double as the evaluation targets (gold pages in `grading_kit/tasks.jsonl`). | Dense `BAAI/bge-m3` (1024-d, cosine via normalized inner product) over FAISS HNSW. Reranker in config: `cross-encoder/ms-marco-MiniLM-L6-v2`; the multilingual `BAAI/bge-reranker-v2-m3` is the candidate to compare. | `k=10`, `k_step=10`, `k_max=40`, `weak_threshold=0.35` on the dense cosine score. Rerank only changes order; `Chunk.score` keeps the dense score so the threshold stays calibrated. | `Retriever.retrieve()` returns chunks with scores; `top_score/is_weak/next_k` are the evidence policy read by `Agent.decide()`; `rerank.rerank()` is a separate, optional step exposed as the `rerank` tool. | Threshold and reranker choice are set from measurements on Kaggle (`scripts/kaggle_a3_check.py` steps 1-2): top-score separation of in-corpus vs out-of-corpus questions, and recall@1/5 with and without each reranker. **Results: TBD.** | Query embedding and HNSW search run on CPU; BGE-M3 loads in ~2.2 GB RAM, so a laptop needs the memory headroom or a Kaggle session. | `scripts/run_eval.py` reports recall@5/10, top-1 page hit (naive baseline) and the rerank ablation delta. |
| **6. Agent** | Answer only from retrieved evidence, with citations; widen the search when evidence is weak and abstain when it stays weak. | Task suite `grading_kit/tasks.jsonl`: 9 + 2 verifiable, 3 judged, 3 out-of-corpus abstention items; gold read from `labels.jsonl`. | Rule-based policy (no learned policy yet). Answer generation: hosted OpenAI-compatible LLM when `llm.provider` is set, otherwise an extractive baseline (best sentence + citation). | Evidence-gated re-search: retrieve at k=10; if top score < 0.35 widen k by 10 (rewriting the query with the LLM when available) up to k=40, then abstain. Grounding gate: answer needs valid `[C#]` citations and >= 30% lexical support in the cited chunks. | Fixed loop in `agent.py`; tools in `agent/tools.py` share one `ToolContext`; guardrails (step/cost budget, approval for state-changing tools, injection masking of retrieved text and rejection of injected queries), PII redaction of answers and traces, HITL queue (sqlite) and JSONL tracing attach through hooks. | Unit tests use a scripted retriever/LLM (`tests/test_agent.py`, `tests/test_crosscutting.py`). The BEFORE_ANSWER seam hands handlers copies, so the abstention verdict is enforced in `synthesize()`, not only in the hook. | Runs on CPU with an API key (or none, extractive). | `traces/run.jsonl` has one line per tool call plus a final answer line with a run id; `eval/metrics.trace_completeness` measures the auditable-NFR target. |

## Active configuration summary

The committed configuration uses CPU for the selected layout, OCR, and
embedding stages. This avoids a false GPU selection on an unsupported `sm_120`
Torch installation. For Kaggle only, use an explicit compatible GPU override in
the standalone batch runner rather than changing the committed baseline.
